# 0007. Naming conventions

- Status: Accepted
- Date: 2026-10-11

## Context

With many pipelines written by agents, inconsistent names are the first thing
that drifts. Conventions in a wiki are not followed; conventions that a tool
generates or rejects are.

## Options

1. Document conventions and check them in review.
2. Enforce them: generate names from the contract wherever possible, and make
   `contractline lint` reject everything else, in CI and as a pre-commit hook.

## Decision

Option 2. Names are generated by `contractline.core.naming`, checked by
`contractline.core.lint`, and configured in `contractline.yaml` (closed domain
list, glossary of approved abbreviations, list of banned abbreviations).

| What | Convention | Example | How |
| --- | --- | --- | --- |
| Contract files | `contracts/<domain>/<entity>.yaml` | `contracts/sales/customers.yaml` | lint |
| Domains | closed set in `contractline.yaml` | `sales` | lint |
| Datasets (logical) | `<env>_<layer>.<domain>.<entity>` | `prod_silver.sales.customers` | generated |
| Ephemeral environments | `pr<number>` as the env | `pr142_silver.sales.customers` | generated |
| Quarantine | layer `quarantine` | `prod_quarantine.sales.customers` | generated |
| Gold models | `<env>_gold.<domain>.<fct\|dim\|agg>_<name>` | `prod_gold.sales.fct_orders` | generated |
| Kafka business topics | `<domain>.<entity>.v<major>` | `sales.orders.v1` | lint |
| Kafka CDC topics | `cdc.<source_system>.<schema>.<table>` | `cdc.crm.public.customers` | lint |
| Columns | snake_case, no banned abbreviation unless in glossary | `customer_id` | schema + lint |
| Harness columns | `_` prefix, reserved | `_ingested_at`, `_op`, `_batch_id` | validator |
| SCD2 columns | fixed | `_valid_from`, `_valid_to`, `_is_current`, `_hash_diff` | generated |
| Timestamps / dates | `_at` (UTC) / `_date`, and only for those types | `updated_at`, `birth_date` | lint |
| Booleans | `is_` / `has_`, and only for booleans | `is_active` | lint |
| Airflow Dag ids | `<domain>__<entity>__<layer>` | `sales__customers__silver` | generated |
| Jobs, infra | `contractline-<env>-<domain>-<entity>`, hyphens | `contractline-prod-sales-customers` | generated |
| Branches | `agent/<TICKET>-<domain>-<entity>`, `feat/`, `fix/`, `chore/`, `docs/` | `agent/DATA-231-sales-customers` | lint (CI) |
| Commits | Conventional Commits | `feat(sales): add customers contract` | lint (commit-msg hook) |
| PR titles | `[<domain>/<entity>] <summary>` (required for agent branches) or Conventional Commit form | `[sales/customers] add SCD2 on segment` | lint (CI) |
| Resource tags | `domain`, `owner`, `contract_version`, `pii` set by the harness; contracts cannot override them | | generated + lint |

Environments are `local`, `dev`, `staging`, `prod` or `pr<number>`.

**Logical versus physical names.** The three-part dataset name is logical.
Local Spark without a catalog only has `database.table`, so the local compute
adapter will map `prod_silver.sales.customers` to
`prod_silver__sales.customers`; the Databricks adapter uses it as is in Unity
Catalog. Contracts and the core only ever see the logical name.

**Abbreviations.** Recognising an abbreviation in general is not possible, so
lint rejects a configured list of common ones (`cust`, `amt`, `qty`, `ts`, ...)
unless the glossary approves them. The list grows as review finds new ones.

**Job names** use the project name, `contractline-`, rather than `harness-`, and
hyphens because many infrastructure resources reject underscores.

## Consequences

- There are no per-file exceptions. Changing a convention means changing
  `contractline.yaml` or the lint module, which needs the maintainer's review.
- The lint runs in CI on the branch name and PR title, and as pre-commit and
  commit-msg hooks.
- An agent cannot invent a new domain; a new domain is a reviewed config change.
